# W8M 中文内容规范

本规范适用于 W8M 中文页面和账户邮件，包括首页、用户手册、注册、登录、邮箱验证、密码重置、错误页以及已登录工作台。新增页面和修改现有模板时均应遵守本规范。

## 写作原则

- 标题说明页面内容或当前任务，不使用口号、承诺或情绪化召唤。
- 正文先说明用户现在可以做什么，再说明限制、下一步和需要联系谁。
- 按用户能观察到的行为描述系统；数据库、缓存、密钥存储和后台任务实现只写入维护文档。
- 行业术语可以保留，但首次出现时要给出中文含义或使用场景。
- 按钮使用明确动作，例如“发送密码重置邮件”“登录广告主工作台”，不用“继续”“立即开启”等模糊文字。
- 不承诺未在产品合同中保证的收益、填充率、流量质量、实时性或投放效果。

## 标准术语

| 使用 | 含义与限制 |
|---|---|
| 广告主 | `adv` 账户。不要写“商家”或“商户”。 |
| 代理商 | `agent` 账户或受托审核人员，不等同于广告主账户或外部 DSP。 |
| 流量方（发布商） | `pub` 账户。首次出现可写全称，后文简称“流量方”；不要使用“媒体主”或“流量源公司”。 |
| 流量源 | 流量方名下的网站、App 或经平台批准的上游接入。 |
| 广告位、流量资源 | 流量方可管理和接入的广告展示位置；避免用“广告库存”作为账户名称。 |
| 广告活动、广告组、广告素材 | 广告主投放层级；需要时可在首次出现处注明 Campaign、Ad Group、Creative。数据库和路由中的 `item` 名称不改变。 |
| 外部 DSP / ADX 需求方接入与竞价 | 对外统一功能名称；“middleman”只作为代码、配置和运维语境中的内部名称。 |
| 登录 | 统一写法。不得使用“登入”或“登陆”。 |
| 注册邮箱、密码重置 | 账户流程的统一用语。 |

## 标题与版式

- 首页主标题为“W8M 广告投放与流量接入平台”。
- 广告主登录页使用“广告投放管理”，流量方登录页使用“流量接入管理”。
- 状态页使用“验证邮件已发送”“账户已激活”“密码重置邮件已发送”“密码已重置”等结果型标题。
- 首页主标题桌面端不超过 42 px，分区标题不超过 32 px，账户页标题不超过 30 px；移动端分别不超过 34、28、28 px。
- 正文原则上不小于 16 px，并保持适合中文阅读的行高；信息密集弹窗中的明细列表可使用 14 px，但须使用至少 1.7 倍行高，标题、导语、状态说明和操作入口仍不小于 16 px。英文全大写、过宽字距和装饰性副标题不用于公共页面。
- 标题、导航和操作控件使用统一的中文界面无衬线字体；导语、说明、卡片正文、弹窗正文和常见问题使用相近但更适合连续阅读的中文无衬线字体栈。流程卡片和平台能力卡片中的辅助说明可使用 14 px 和至少 1.6 倍行高，标题与查看说明入口保持更明显的层级。

## 首页平台能力

- 首页顶部特性条使用“DSP、SSP 与 ADX 一体化工作流”“OpenRTB 2.5 受控兼容与开放 API”“隐私信号、流量质量与运行观测”，概括可核验的平台范围，不使用“最新”“最强”或其他无法客观验证的口号。
- “平台能力”使用八个可点击卡片和对应详情弹窗，覆盖 DSP、SSP、外部 DSP / ADX、OpenRTB、测量与分析、隐私与身份、流量质量、账务支付、管理 API 和生产运行。
- 八个平台能力卡片及其弹窗统一使用“测量、归因与分析”的紫色视觉方案；功能类型和启用边界由标题与正文说明，不再用不同颜色表达。
- 首页不显示内部里程碑编号。文案只描述已经实现的行为，并把“已实现”“默认关闭”“需要合作方灰度”及“按具体需求提供”区分清楚。
- OpenRTB 统一写为“OpenRTB 2.5 受控兼容规范”，不得暗示支持协议的所有可选扩展或获得外部合规认证。
- App 可使用当前 `/pz` 协议与 JSON/OpenRTB 返回；在没有可维护发布物前，不把 SDK/API 样例称为已经提供的 Android/iOS 原生 SDK。
- 双重验证与细粒度权限、流量质量、广告主管理 API、托管支付和外部需求方流量均说明启用前置条件；不得因代码存在就写成生产环境已开放。
- 单区域可用性只说明技术机制与证据要求；没有连续生产测量和服务商恢复记录时，不宣称已经达到 99.9% 或生产 RPO/RTO。

## 首页角色指南

- “使用指南”先用广告主和流量方两个页签概述四步流程，再分别提供一个详细弹窗；弹窗内容以对应完整中文手册为准，不在首页另造产品规则。
- 广告主弹窗说明账户、广告活动、广告组、广告素材和定向的配置顺序，并明确“已保存”、运营审批、运行缓存与生产投放之间的边界。
- 广告主和流量方的全部八个流程步骤均使用可点击卡片和独立弹窗。卡片必须有可见的查看说明提示，并支持键盘焦点；弹窗应说明字段用途、后续配置、上线边界和常见排查顺序。
- 流量方弹窗说明流量源、广告位、网页广告码与 App/API 接入，强调使用最新令牌、来源校验、隐私信号、安全渲染以及正常无填充语义。
- 两个弹窗均保留工作台和完整手册入口；首页只提供可完成首次配置和排查的摘要，完整字段、示例、错误表和验收清单仍由角色手册维护。
- 广告主沿用暖色，流量方沿用冷色；弹窗在移动端改为纵向步骤，并保持正文不小于 16 px、键盘焦点可见和明确的关闭按钮。

## 错误与账户邮件

- 公共错误页说明用户可采取的下一步，不显示原始框架、数据库或配置错误；错误编号可以作为支持参考。
- 找回密码结果始终使用“如果该邮箱已注册，我们将发送密码重置链接”，不得泄露账户是否存在。
- 邮件主题先写品牌和账户类型，再写任务，例如“W8M 广告主账户邮箱验证”。
- 邮件使用“您好，姓名：”开头，说明链接用途，并以“W8M 广告平台”署名；未配置有效期时不写具体时限。

## 维护检查

中文页面改动后运行：

```bash
GOWORK=off go run ./tools/check-templates.go -ext=.g
GOWORK=off go run ./tools/check-public-copy
git diff --check
```

Aofei 下的广告主/代理商和流量方 Markdown 手册是内容基准；`www/manuals/` 中的公共 HTML 应在同一批变更中同步更新。

页面文案和数据库字段一律作为普通字符串交给 `html/template`，不得为保留排版而转换为原始 HTML。素材管理和审核页面只显示经过转义的素材源内容，不加载素材地址，也不执行素材代码。涉及链接、报表脚本、邮件或素材展示的修改，还必须遵守 [rendering-security.md](rendering-security.md) 并运行其中的恶意输入回归测试。
