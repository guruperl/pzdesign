广告主与代理商使用手册

1. 账户与职责

平台地址、账户开通、商务规则和生产凭据由运营方另行提供。广告主页面位于 /goto/adv/g/...，代理商页面位于 /goto/agent/g/...。

角色主要职责
广告主（adv）维护自己的账户、广告活动、广告组、广告素材、定向、预算、投放报表和竞价端点。
代理商（agent）受托查看广告主、广告活动和广告组，并执行被授权的审核流程。
平台运营人员（admin）管理账户状态、竞价端点凭据与启用、外部需求方路由、流量分配和结算视图。
注意：代理商账户不是另一个广告主账户，也不会自动获得广告主的全部编辑权限。审批、凭据、路由或生产启用需要平台运营人员处理。

如果现有密码无法登录，请使用登录页的“忘记密码”功能，或联系平台运营方确认账户状态。

注册与找回密码：提交前可能需要完成 Cloudflare 人机验证，用于限制批量注册和垃圾邮件。验证失效时请刷新页面；提示提交过于频繁时请稍后再试，不要连续点击。持续无法提交可联系 support@w8m.com。

2. 投放对象层级

广告主账户
└── 广告活动 （Campaign）
    └── 广告组 （Ad Group，系统内部对象名为 Item）
        └── 广告素材 （Creative）
  • 广告活动定义名称、投放时间、流量范围、活动级预算和启用状态。
  • 广告组定义价格、计费方式、落地页、频次控制、广告组预算和定向条件。
  • 广告素材定义尺寸、媒体类型、内容、权重和启用状态。

一次请求只有在账户、广告活动、广告组、广告素材、时间、预算、尺寸、定向和供应侧规则都允许时，才可能参与竞价。只启用最下层广告素材，不能绕过上层状态或规则。

3. 推荐投放流程

1

检查账户资料

核对账户名称、联系人、地址和密码。投放账单、人工调整及账户启用状态以平台运营方出具的记录为准；页面显示“已保存”不代表已经具备生产投放资格。工作台不采集完整银行卡号或银行账户信息。

2

创建广告活动

填写活动名称、起止时间、流量范围、总预算、每日预算和状态。建议先保存为未启用，完成广告组、广告素材与定向检查后再启用。

3

创建广告组

设置计费方式、价格、落地页、起止时间、预算、展示/点击频次，以及语言、设备、地域、流量方、行业和其他定向规则。

4

添加并测试广告素材

填写素材名称、尺寸、媒体类型、内容、权重和状态。素材尺寸必须与目标广告位一致，并在测试环境检查展示和最终点击跳转。

5

逐步配置定向

建议先用较宽规则完成小流量验证，再逐项收紧。无投放时按“状态与时间 → 预算 → 尺寸 → 供应侧流量范围 → 人群定向”排查。

价格、币种与频次

  • 当前实时竞价价格以 USD CPM（千次展示价格）参与比较。系统不进行其他币种换算。一个有效展示的账务金额按 CPM / 1000 计算，例如 CPM 为 2.5 时计入 USD 0.0025。
  • 频次控制只在平台隐私决策允许个性化处理时使用买方用户 ID、用户 ID 或 IFA/设备 ID；写入状态前会转换为域隔离假名。
  • 平台不会将 IP 与 User-Agent 拼成后备身份。缺少合规身份时仍可做上下文投放，但跨请求频控和上传人群不会生效。

广告素材跟踪规则

  • 原生和原生视频素材带 DSP 展示跟踪，并以 DSP 点击跳转地址作为主链接。
  • Banner iframe 带展示像素；需要 DSP 点击测量时，内容 URL 或模板必须显式使用 {CLICK_URL}。
  • {LANDING_URL} 表示直接广告主落地页；系统不会重写任意第三方 iframe 或 HTML 内部链接。
  • 不要修改平台生成的 /imp、/clk、sig 或 sig_ts 参数。

支持的定向类型

  • 地理：国家、州/省、城市、DMA、ISP、邮编、经纬度和连接类型。
  • 人群：性别、年龄/出生年份区间和语言。
  • 设备：操作系统、版本、浏览器/平台和设备类型。
  • 时间：日期、小时、星期和时区。
  • 供应与内容：流量方、网站/App、广告位、行业及流量范围。
  • 上传人群：广告主上传的用户或设备标识集合。
上传人群：配置多个上传标识类型时，请求必须同时包含并命中每个已配置类型。上传人群命中具有优先层级，配置时应避免意外排除其他候选。

4. 报表与计量口径

广告主仪表盘和报表可查看近 24 小时数据、主要广告组和主要广告位。数据由日志聚合与账务定时任务生成，并非请求级实时数据。

指标当前口径
展示有效 /imp 跟踪到达后计入。
点击有效 /clk 跟踪到达后计入。
花费以有效展示跟踪记录中的 USD CPM 除以 1000 计算。
Win/Loss用于分析，不单独作为当前账务花费依据。

系统会尽力抑制重复的有效展示和点击事件。共享状态服务暂时不可用时，平台仍优先接收签名有效的测量事件，因此短时间内可能出现重复计量。

账单与人工结算

平台运营方可按 UTC 日、UTC 自然周或 UTC 自然月，从已完成的日账务汇总生成广告主账单。账单经过草稿、暂停、确认、结算登记或更正流程，调整必须保留原因；已确认记录的更正会保留原账单，不会回写展示事实或降低投放预算硬上限。

如需账单或 CSV，请向运营方提供账户 ID 和账期。不要通过工作台、邮件或工单发送完整银行卡号、银行账号或路由号码。

5. 外部 DSP / ADX 需求方接入与竞价

经营外部 DSP 的广告主可在“竞价端点”维护端点名称、HTTP/HTTPS URL、OpenRTB 版本、Seat 和超时时间：

/goto/adv/g/bidder?action=topics

端点身份凭据、审批与启用、流量范围、路由、加价和报表归属由平台运营方管理。请通过约定的安全渠道提供密钥，不要将密钥写入端点名称、URL 或其他普通表单字段。

可能的触发方式

  • Fallback：仅在本地广告无法填充时请求外部端点。
  • Always：只有平台总开关和独立 Always 开关均启用时，外部竞价才可与本地广告竞争。

外部 DSP 注意事项

  • 迟到、非法、低于底价或非 USD 的响应会被丢弃。
  • 平台保留下游广告代码，但用平台签名的 /mid/* 地址代理 win、loss 和 bill 回调。
  • burl 优先作为可计费事件；没有 burl 时，win 才是回退。
  • 端点接入不代表无条件获得全部流量，仍需满足运营方配置的流量方、流量源和广告位范围。
新增或修改端点后，请等待运营方完成审批、身份凭据和流量路由配置，再进行流量测试。

6. 常见问题

有广告素材但没有竞价

检查上层对象是否启用、时间和预算是否有效、尺寸是否匹配、竞价底价币种是否为 USD，以及定向、行业和供应侧流量范围是否过窄。

有 win 但报表没有展示或花费

当前账务以展示跟踪为准。检查素材中的展示像素是否被客户端加载，并确认报表处理时间已覆盖对应测试时段。

Banner 有展示但没有点击

确认素材显式使用 {CLICK_URL}。系统不会自动包装任意 iframe 内部链接。

竞价端点已保存但没有流量

保存端点信息不等于已经启用。请运营方检查端点审批、身份凭据、流量范围、路由状态和平台功能开关。

7. 上线检查清单

  • 广告主、广告活动、广告组和至少一个广告素材均处于可投放状态。
  • 当前时间位于广告活动和广告组的投放区间。
  • 总预算和每日预算未耗尽。
  • 素材尺寸与目标广告位一致。
  • 落地页与第三方监测地址可从公网访问。
  • Banner 需要点击测量时已使用 {CLICK_URL}。
  • 价格与竞价底价使用兼容币种，定向和流量范围没有互相排斥。
  • 运营方已确认修改进入运行缓存。
