流量方（发布商）接入手册

面向通过 W8M 管理网站、App 和广告位，并使用网页广告码或 POST /pz 接口接入广告服务的流量方（发布商）。

1. 账户与流量资源层级

流量方账户用于管理网站、App 和广告位。登录页面位于 /goto/pub/g/...。

流量方账户 （发布商）
└── 流量源 （网站或 App）
    └── 广告位

仪表盘可查看主要广告位、主要广告活动和近 24 小时数据。报表由后台日志和账务任务定时汇总，不是请求级实时数据。

注册与找回密码：提交前可能需要完成 Cloudflare 人机验证，用于限制批量注册和垃圾邮件。验证失效时请刷新页面；提示提交过于频繁时请稍后再试，不要连续点击。持续无法提交可联系 support@w8m.com。

账户资料中的“卖方透明度”用于说明由谁销售广告资源，包括卖方 ID、类型、广告系统域名（ASI）、公开名称和域名。资料须经平台运营方复核；已授权内容一旦改变会恢复为待审核。这些资料用于 OpenRTB 供应链和报表分类，不改变当前流量方账户的收入归属、结算主体或收款方式。

2. 创建流量源

进入“流量源/站点”后选择新增，并检查：

  • 流量源名称与类型：Web 或 App。
  • Bundle/Domain：网站填写域名，Android App 填包名，iOS App 填商店数字 ID。
  • 流量环境与规范标识：网站填写审核域名，App 填写包名或应用标识。
  • 公开审核地址只填写不含账号密码的 http 或 https 页面。
  • 接入方式选择 ADX、网页广告码、SDK 或服务端 API，并与 Web/App 类型保持一致。
  • 介绍网址、流量范围（白名单/黑名单）和启用状态。
Web 来源校验：生产页面发送的 Origin 或 Referer 主机名必须与平台缓存中的站点主机名完全一致。不同子域名不会自动视为同一站点。

修改流量源后，如果生成的接入代码仍被拒绝或继续使用旧数据，请联系运营方刷新静态缓存；广告请求链路不会直接查询数据库。

3. 创建广告位

在流量源下选择“添加广告位”，配置广告位名称、宽高、最低竞价（USD CPM）、语言、设备平台、页面位置、可接受媒体类型、素材特点、质量条件、行业规则和状态。

  • 广告位保存的尺寸是运行时可信尺寸。
  • 浏览器或 SDK 请求中自报的宽高不能覆盖平台配置。
  • 请求令牌携带的尺寸与缓存配置不一致时，服务会返回 400。
  • 最低竞价是服务端权威底价；请求可以提高但不能降低，实际采用两者中的较高值。
  • 选择媒体形式意向、展示位置、渲染场景、广告密度、流量审核状态、资源来源和管理责任方。
  • 刷新方式可为不刷新、定时刷新或事件触发；定时刷新须填写 15 至 3600 秒。
  • 修改尺寸后，应重新取得接入代码，不要继续使用旧 slot 令牌。

4. 获取并部署网页广告码

广告位列表会按流量源类型给出接入方式：Web 只显示网页广告码，App 只显示 SDK/API 代码。推荐直接使用页面生成的样例，其中的 site 和 slot 是平台生成的打包标识，不要猜测、截断、交换或手工改写。

<script src="https://w8m.com/js/ads.js"></script>
<div id="pz-slot-13" style="width:300px;height:250px"></div>
<script>
pzLoadAds({
  "platform": "browser",
  "site": "<页面生成的 site 令牌>",
  "adUnits": [{
    "code": "pz-slot-13",
    "slot": "<页面生成的 slot 令牌>",
    "mediaTypes": {"banner": {"size": [300, 250]}}
  }]
});
</script>

ads.js 默认根据自身脚本地址推导 /pz 服务地址。若静态文件和广告服务不在同一地址，可显式指定：

pzLoadAds(payload, { endpoint: "https://w8m.com/pz" });

部署注意事项

  • adUnits[].code 是页面 DOM 元素 ID 和响应顺序标识，不是流量资源身份；同一请求内非空值必须唯一。
  • site 标识流量方账户和流量源，slot 标识广告位与尺寸。
  • 支持 banner、video 和 native 媒体类型。
  • 浏览器请求必须携带有效来源，所有出现的来源主机都必须与缓存站点完全一致。
  • /pz 跨域访问不携带凭据，不能依赖跨站 Cookie 一定可用。
素材隔离：ads.js 把填充素材放进不带 allow-same-origin 的独立沙箱 iframe，并把容器标记为 filled、no-fill 或 error。请勿移除沙箱或把返回字符串直接写入宿主页的 innerHTML。

HTML 响应

省略 responseFormat 或使用 html 时，成功响应是按广告位输入顺序排列的 HTML 字符串数组。未填充位置用空字符串表示：

["<iframe ...></iframe><img ...>", ""]
合法请求即使全部无填充也返回 200。前端应隐藏或回收空结果的容器，不要将 no-fill 当成网络错误快速重试。

5. SDK 与服务端 API 接入

SDK 请求发送至：

POST https://w8m.com/pz
Content-Type: application/json

建议使用广告位页面“API码”中的实际令牌：

{
  "platform": "sdk",
  "responseFormat": "json",
  "site": "<页面生成的 site 令牌>",
  "app": {"bundle": "example.com"},
  "adUnits": [{
    "code": "pz-slot-13",
    "slot": "<页面生成的 slot 令牌>",
    "mediaTypes": {"banner": {"size": [300, 250]}}
  }]
}
  • 本样例为上下文请求，特意省略用户和设备标识。SDK 可提供 OpenRTB 风格的 app、device、user 和 regs 对象。
  • 只有平台隐私决策允许个性化处理时，device.ifa、设备 ID、user.id 与 buyeruid 才会进入本地匹配；上下文或受限模式会删除这些标识。
  • 流量方必须从已审核的 CMP/隐私流程传递适用的 GDPR/TCF、GPP/US Privacy、COPPA、GPC/DNT/LMT 信号，不得伪造同意授权。
  • app.id、app.bundle 或 app.domain 如提供，必须与平台验证出的流量源身份一致。
  • SDK 可省略 Origin 和 Referer，但只要提供就必须通过主机校验。
responseFormat响应
省略或 html每个广告位对应一个 HTML 字符串。
json每个广告位对应一个结构化的填充/未填充对象。
openrtb一个 OpenRTB BidResponse；全部无填充时 seatbid 为空。

客户端负责按广告类型安全展示 adm，并在使用结构化响应时按协议触发展示或点击测量。不要修改平台生成的签名参数。

6. 浏览器身份、隐私与代理

  • 浏览器接入只有在当前请求通过已配置的个性化授权后，才可使用 aofei_pz_uid 作为尽力而为的假名身份。
  • 缺失、拒绝、退出、无效、COPPA 或尚未映射的 GPP 信号不会读取或设置 Cookie。
  • Cookie 因跨域策略缺失时不阻止上下文投放；系统不会将 IP 与 User-Agent 拼成后备身份。
  • SDK 请求完全不读取、设置或传递该 Cookie，应提供合规的设备或用户标识。
  • 只有 CDN 或反向代理出口已由运营方加入受信列表时，服务才会采用 X-Forwarded-For 或 X-Real-IP。
流量方不应伪造代理请求头。如流量经过 CDN 或反向代理，请与运营方共同验证代理链路和真实客户端地址。

7. 填充、测量与报表

通过 /pz 投放的本地素材复用平台的签名展示和点击测量。账务中的展示与结算金额以有效展示跟踪到达为基础，点击以有效点击跟踪到达为基础。竞价价格使用 USD CPM（千次展示价格）；一个有效展示对应的账务金额按 CPM / 1000 计算，例如 CPM 为 2.5 时计入 USD 0.0025。

当平台启用外部 DSP / ADX 需求方竞价时，本地无填充可使用 Fallback 路由；只有独立 Always 开关同时启用时，外部竞价才可与本地广告竞争。这些选择对流量方接入协议透明，无需修改 ads.js 或请求结构。

市场分析可按流量环境、接入方式、媒体形式、展示位置、刷新方式、质量分类和已授权卖方查看数据。历史或未填写的分类明确显示为 Unknown，未经授权的卖方不会归入某个卖方 ID。报表由日志聚合与账务任务定时生成；持续缺失时，请向运营方提供时间范围、流量源、广告位和请求结果。

结算单

平台运营方可按 UTC 日、UTC 自然周或 UTC 自然月，从已完成的日账务汇总生成流量方结算单。结算单经过草稿、暂停、确认、结算登记或更正流程；已确认记录的更正会保留原结算单，不会回写展示事实。

如需结算单或 CSV，请向运营方提供账户 ID 和账期。不要通过工作台、邮件或工单发送完整银行卡号、银行账号或路由号码。

8. 错误与排查

现象常见原因处理
400JSON 或令牌错误、广告位不存在、Web/App 类型不符、尺寸或底价非法、媒体类型不是唯一一项、code 缺失/非法/重复使用广告位页面最新样例，逐项核对请求字段。
403浏览器来源缺失或主机不完全匹配核对生产页面主机、Origin、Referer 和缓存站点。
413请求体超过限制减少单次请求广告位数量或无关字段。
200 且为空请求合法，但没有匹配广告当作正常 no-fill；排查时提供时间和广告位。
页面没有渲染DOM ID 不一致、脚本失败、CSP/网络拦截或未处理空响应检查浏览器控制台、网络请求和容器 ID。
修改后仍是旧行为运行缓存尚未发布联系运营方刷新缓存并确认生成时间。
报表延迟日志轮转或账务时间片尚未完成等待计划任务；持续缺失时提供时间范围。

9. 上线验收清单

  • 流量源类型、Bundle/Domain、站点主机和状态正确。
  • 流量环境、规范标识、接入方式和公开审核地址正确。
  • 广告位尺寸、服务端最低竞价、媒体形式、展示位置、刷新和质量规则正确。
  • 卖方资料已由平台运营方审核；资料变更后已重新复核授权。
  • Web 只使用网页广告码，App 只使用 SDK/API 样例。
  • 使用广告位页面最新生成的 site 与 slot 令牌。
  • 浏览器实际 Origin/Referer 与缓存站点完全一致。
  • 每个非空 code 在请求内唯一，并有对应 DOM 容器。
  • 测试至少一次有填充和一次无填充响应。
  • SDK 不依赖 Cookie，并提供合规的设备或用户标识。
  • 与运营方确认缓存刷新、报表延迟和故障联系渠道。
