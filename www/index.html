广告主使用流程 · 第 1 步

创建和检查广告活动

广告活动（Campaign）是广告组和广告素材的上层投放边界，用于统一控制活动周期、流量范围、活动级预算和状态。建议先保存为未启用，完成下层配置和测试后再上线。

需要确认的活动字段

  • 名称：使用便于团队识别和报表检索的活动名称，避免把密钥或个人信息写入名称
  • 投放周期：填写明确的开始与结束时间，并确认当前时间位于有效区间
  • 流量范围：选择与投放目标相符的供应范围；过窄或互相排斥的范围可能没有合格流量
  • 总预算与每日预算：为活动设置明确上限，并确认两项预算都未耗尽
  • 状态：准备阶段保持未启用，完成广告组、素材、定向和小流量测试后再启用

保存后的配置顺序

  • 在活动下创建广告组，设置 USD CPM 价格、落地页、广告组预算、时间和频次
  • 添加至少一个尺寸、媒体类型和目标广告位相符的广告素材
  • 先用较宽的地域、设备、人群和供应定向完成小流量验证，再逐项收紧
  • 确认账户、活动、广告组和素材状态一致，并等待修改进入运行缓存
  • 上线后观察有效展示、点击和花费报表；报表由后台任务汇总，并非请求级实时
没有竞价时：依次检查账户与活动状态、活动时间、总预算和每日预算、广告组状态、素材尺寸、USD 底价、流量范围和定向条件。只启用活动本身不会绕过下层规则。

广告主使用流程 · 第 2 步

配置和检查广告组

广告组（Ad Group）位于广告活动之下，用于确定实际竞价价格、落地页、广告组预算、频次和定向条件。同一活动可以建立多个广告组，分别服务不同受众或供应范围。

价格、时间与频次

  • 竞价价格：商业投放使用正值 USD CPM，并确保价格能够满足目标广告位的服务端最低竞价
  • 落地页：填写可从公网访问的 HTTPS 地址，并分别验证直接访问和最终跳转
  • 时间与预算：广告组日期应位于活动周期内，并设置适当的总预算和每日预算
  • 频次：按业务需要设置展示/点击上限和最小展示间隔，避免测试条件过严
  • 状态：准备阶段保持未启用，至少添加并测试一个素材后再与上层活动一起启用

定向配置与验证

  • 可按国家、省/州、城市、语言、设备类型、操作系统、浏览器、日期、小时和星期配置定向
  • 供应侧条件可限制流量方、网站/App、广告位、行业、频道和活动允许的流量范围
  • 上传人群按配置的标识类型匹配；多个标识条件可能要求请求同时命中
  • 建议先用较宽的单一条件完成小流量测试，再逐项加入其他条件并观察候选变化
  • 启用前核对活动和广告组的时间、预算、状态没有冲突，并等待运行缓存刷新
价格边界：当前商业投放以 USD CPM 参与竞价。历史 CPC、CPA 或 ROI 字段不会自动转换为可投放价格；没有候选时应同时检查底价、定向和供应范围。

广告主使用流程 · 第 3 步

添加和测试广告素材

广告素材（Creative）定义最终展示内容。只有启用状态、尺寸、媒体类型和请求条件均匹配的素材，才会进入已获胜广告组内部的权重轮播。

素材字段与匹配条件

  • 填写清晰的素材名称、宽高、媒体类型、素材内容、权重和启用状态
  • Banner、Video 与 Native 应使用各自支持的内容结构；尺寸必须与目标广告位完全一致
  • 素材权重只影响同一获胜广告组内的素材选择，不会提高广告组对其他广告组的竞价优先级
  • 素材 URL、回调地址和引用资源应使用可访问的 HTTPS 地址，并符合相应媒体格式
  • 先使用单一素材完成展示和点击测试，再增加其他尺寸、版本或权重组合

展示与点击测试

  • Banner 需要平台点击测量时，在内容 URL 或模板中显式使用 {CLICK_URL}
  • {LANDING_URL} 表示直接落地页；平台不会自动重写任意第三方 iframe 或 HTML 内部链接
  • 不要修改平台生成的 /imp、/clk、sig 或 sig_ts 参数
  • 测试时确认素材实际加载、展示跟踪到达、点击跳转正确，并检查浏览器控制台和网络请求
  • Video 检查 VAST 资源和 MIME，Native 检查必需资产，避免只验证预览而未验证真实广告位
匹配边界：只启用素材不能绕过账户、广告活动或广告组状态，也不能绕过时间、预算、尺寸、底价、定向和供应侧规则。

广告主使用流程 · 第 4 步

上线投放并查看报表

上线前先完成对象状态、预算、时间、尺寸、落地页、跟踪和运行缓存检查；上线后使用统一的展示、点击和花费口径观察投放，而不是仅凭保存状态判断是否已经生效。

上线前检查

  • 广告主账户、广告活动、广告组和至少一个广告素材均处于可投放状态
  • 当前时间位于活动和广告组的有效周期，总预算与每日预算均未耗尽
  • 素材尺寸和媒体类型与目标广告位一致，落地页及第三方测量地址可以访问
  • 需要点击测量的 Banner 已使用 {CLICK_URL}，测试展示和点击链路均成功
  • 价格与广告位底价使用兼容的 USD CPM，定向与流量范围没有互相排斥，修改已进入运行缓存

报表与计量口径

  • 展示：有效、签名正确的 /imp 跟踪到达后计入
  • 点击：有效、签名正确的 /clk 跟踪到达后计入
  • 花费：按有效展示记录中的 USD CPM 除以 1000 计算
  • Win/Loss：用于竞价分析，但不单独作为当前账务花费依据
  • 仪表盘可查看近 24 小时和主要对象；持续缺失时提供测试时间、活动、广告组和广告位信息
数据时效：报表由日志聚合与账务任务定时生成，不是请求级实时数据。上线初期应保留测试时间和对象信息，并为后台处理预留合理时间。

流量方接入流程 · 第 1 步

创建和审核流量源

流量源代表流量方账户名下的网站或 App，是广告位、来源验证和供应透明度的上层边界。先确定 Web/App 类型和真实身份，再选择与该类型一致的接入方式。

流量源身份与接入类型

  • 类型：网站选择 Web；移动应用选择 App，保存后接入代码会按类型区分
  • Bundle/Domain：网站填写正式域名，Android 填写包名，iOS 填写商店数字 ID
  • 审核标识：填写对应的审核域名、包名或应用标识，并提供无需账号密码的公开审核地址
  • 接入方式：选择 ADX、网页广告码、SDK 或服务端 API，并确保与 Web/App 类型一致
  • 范围与状态：配置允许或拒绝的流量范围，并在资料和广告位准备完成后再启用

审核、透明度与缓存

  • 浏览器生产页面的 Origin 或 Referer 主机必须与缓存中的站点主机完全一致
  • 不同子域名不会自动视为同一站点；正式上线前应逐个确认实际请求来源
  • 卖方 ID、类型、广告系统域名、公开名称和域名等透明度资料需经平台运营方复核
  • 已授权卖方资料发生变化时会恢复为待审核，不应继续按旧资料对外披露
  • 修改流量源后如接入仍使用旧数据，应联系运营方刷新运行缓存并确认生成时间
来源边界：Web 请求缺少来源或主机不完全匹配时会被拒绝。不要用测试域名、其他子域名或请求参数替代平台登记的正式站点身份。

流量方接入流程 · 第 2 步

配置和检查广告位

广告位定义实际可售展示位置的可信尺寸、服务端底价、媒体形式和质量要求。客户端请求可以提供更多上下文，但不能降低或覆盖平台保存的核心配置。

广告位核心配置

  • 填写便于运营和报表识别的广告位名称，并设置准确的宽度和高度
  • 最低竞价使用正值 USD CPM；服务端采用平台底价与请求底价中的较高值
  • 选择 Banner、Video 或 Native 等可接受媒体类型，并设置设备、语言和页面位置
  • 按业务需要配置素材特点、质量条件、行业规则、流量审核状态和管理责任方
  • 刷新方式可为不刷新、定时刷新或事件触发；定时刷新间隔须为 15 至 3600 秒

运行时可信边界

  • 广告位保存的尺寸是运行时可信尺寸，浏览器或 SDK 自报宽高不能覆盖
  • 请求令牌中的尺寸与缓存配置不一致时，服务会返回 400
  • 请求可以提高底价但不能降低平台底价，避免客户端绕过商业规则
  • 修改尺寸、流量源身份或关键配置后，应重新取得接入样例和最新 slot 令牌
  • 启用前确认所属流量源已审核、广告位状态正确，并等待配置进入运行缓存
令牌边界：不要手工修改、交换或复用旧广告位令牌。尺寸或关键配置变化后，必须从广告位页面重新获取最新接入代码。

流量方接入流程 · 第 3 步

部署网页广告码或 App/API

Web 流量使用页面生成的网页广告码，App 或服务端接入使用对应的 API 样例。两种方式都请求 POST /pz，并使用平台生成的 site 与 slot 令牌标识资源。

网页广告码

  • Web 流量源只使用广告位页面生成的网页广告码，并在页面中创建匹配的 DOM 容器
  • adUnits[].code 是容器 ID 和响应顺序标识；同一请求中的非空值必须唯一
  • site 标识流量方与流量源，slot 标识广告位与尺寸，二者不能交换或手工改写
  • ads.js 默认推导同源 /pz 地址；静态资源和广告服务分离时才显式指定 endpoint
  • 网页样例把素材放入无同源权限的沙箱 iframe；不要移除沙箱或直接写入宿主页 innerHTML

App 与服务端 API

  • App/API 使用 JSON 请求，可按场景选择 HTML、结构化 JSON 或 OpenRTB BidResponse
  • 如提供 app.id、app.bundle 或 app.domain，必须与平台验证的流量源身份一致
  • 传递真实、适用的 TCF、GPP、COPPA、GPC/DNT/LMT 等隐私信号，不得伪造同意授权
  • SDK 请求不读取或依赖浏览器 Cookie；只有隐私决策允许时才传递合规的设备或用户标识
  • 结构化响应由接入方按媒体类型安全渲染，并按协议触发展示和点击测量
移动接入说明：当前提供 /pz 协议、JSON/OpenRTB 返回和 SDK/API 样例；维护型 Android/iOS 原生 SDK 需在具体集成需求确认后提供。

流量方接入流程 · 第 4 步

验证接入并查看报表

上线验收同时覆盖资源身份、请求格式、填充与无填充、安全渲染、测量和报表。请保留测试时间、流量源、广告位、来源页面和响应结果，便于定位缓存或匹配问题。

请求与响应验收

  • 确认流量源类型、Bundle/Domain、广告位尺寸、服务端底价、媒体类型和状态正确
  • Web 请求核对 Origin/Referer，App 请求核对应用身份、隐私信号和平台类型
  • 至少验证一次有填充响应，并确认 DOM 容器、沙箱渲染、展示和点击测量正常
  • 同时验证一次无填充；合法请求返回 200 空结果属于正常情况，不应快速重试
  • 400 通常表示字段、令牌或尺寸问题；403 表示来源问题；413 表示请求体过大

测量、报表与结算

  • 有效展示和点击分别在签名跟踪到达后计入，账务展示金额按 USD CPM ÷ 1000 计算
  • 仪表盘和报表可按主要广告位、主要广告活动及近 24 小时数据观察表现
  • 报表由日志聚合和账务任务定时生成，不是请求级实时数据
  • 修改后仍是旧行为时，先确认运行缓存生成时间；持续缺失时提供完整测试上下文
  • 需要结算单或 CSV 时向运营方提供账户 ID 和账期，不要通过普通表单或邮件发送完整银行资料
无填充语义：200 且内容为空表示请求合法但当前没有匹配广告。客户端应隐藏或回收空容器，并按正常流量节奏继续请求。

广告主 / 代理商

广告投放详细使用指南

广告主负责自己的投放对象与报表；代理商仅在授权范围内查看或审核。建议按账户、广告活动、广告组、广告素材和定向的顺序配置，再进行小流量验证。

1账户资料2广告活动3广告组4广告素材5验证上线

账户、层级与投放配置

  • 广告活动：设置名称、起止时间、流量范围、总预算、每日预算和启用状态
  • 广告组：设置 USD CPM 价格、落地页、预算、展示/点击频次以及地域、设备、人群和供应定向
  • 广告素材：核对 Banner、Video 或 Native 的尺寸、媒体类型、内容、权重和启用状态
  • 建议先使用较宽规则完成小流量验证，再逐项收紧定向，避免多个条件互相排斥
  • 经营外部 DSP 时可维护竞价端点；身份凭据、审批、流量范围和路由仍由平台运营方配置

上线、测量与问题排查

  • 账户、广告活动、广告组和至少一个广告素材必须同时处于可投放状态，时间、预算和尺寸也须匹配
  • Banner 需要平台点击测量时显式使用 {CLICK_URL}，不要修改签名展示或点击参数
  • 展示和点击分别在有效跟踪到达后计入；花费按有效展示对应的 USD CPM ÷ 1000 计算
  • 报表由日志和账务任务定时汇总，不是请求级实时数据；排查时记录测试时间与对象信息
  • 无竞价时依次检查状态与时间、预算、尺寸、供应范围、底价币种和定向条件
上线边界：页面显示“已保存”不代表已经进入生产投放。请确认上层对象状态、运行缓存和需要运营方审批的配置均已生效。

广告主投放 · DSP

DSP 投放与竞价

以可预测的 CPM 竞价、强制投放边界和严格素材校验组成广告主投放主链路。

投放控制

  • 广告主、广告活动、广告组和广告素材的完整管理层级
  • 总量与每日花费、展示、点击上限，以及起止日期和每周投放时段
  • 快速与均匀两种确定性投放节奏，不以自动模型改写预算
  • 地域、设备、语言、媒体、行业、频道和上传人群等多维定向
  • 用户级展示/点击频次与最小展示间隔控制

竞价与素材

  • 商业投放采用正值 USD CPM；最高合格广告组价格优先
  • 素材权重仅在获胜广告组内部轮播，不改变跨广告组竞价顺序
  • Banner、Video 与结构化 Native 素材按尺寸、媒体类型和 MIME 匹配
  • HTTPS、回调地址、Native 资产和 VAST 资源在进入竞价前校验
  • 共享 Redis 原子预算预留，失败与回调按明确规则释放或确认
计价边界：当前商业竞价为 USD CPM；历史 CPC、CPA、ROI 数据不会被静默转换为可投放价格。

SSP 直连流量变现

以流量方账户、流量源和广告位为所有权边界，为网站与 App 提供统一的直连接入和商业审核流程。

接入与返回

  • 支持有序 HTML、JSON 和 OpenRTB 返回，以及明确的正常无填充语义
  • 服务端使用平台底价与请求底价中的较高值，客户端不能降低广告位底价

供应管理与透明度

  • 网站、App、广告位、尺寸、媒体形态、位置、刷新和质量分类
  • 流量方提出卖方资料，平台审核后才可用于外部披露

  • 流量来源、卖方类型与供应分类进入隐私安全的报表维度

交易互通 · ADX / OpenRTB

ADX 与 OpenRTB 互通

面向广告交易平台和外部 DSP 的 OpenRTB 2.5 受控兼容规范，强调可互通、可诊断和逐竞价方隔离。

协议兼容

  • OpenRTB 2.5 请求与响应，支持独立处理多展示位
  • Banner、Video、Native 和 USD CPM/底价的明确兼容规则
  • 协商式 gzip 请求/响应，并分别限制压缩前后正文大小
  • 严格校验请求 ID、展示位 ID、Seat、媒体、尺寸、价格、币种和时限
  • 回调、素材与落地地址执行 HTTPS、协议和安全目标检查

外部需求方竞价

  • 广告主名下的竞价端点，平台负责凭据引用、审核、路由和流量范围
  • Fallback 用于本地无填充；可选 Always 模式参与有效 CPM 竞争
  • 每个竞价方只接收分配给自己的展示位和独立清理后的上下文请求
  • 无效、迟到或低于底价的外部响应不能替换合格的本地结果
  • 代理 win/loss/展示/点击回调，重试可恢复失败并生成 charge/pay/margin 事实
启用边界：OpenRTB 支持的是经过验证的兼容子集，不无条件透传所有可选扩展。外部需求方流量需完成端点、凭据、路由、隐私披露和灰度验收后单独启用。
测量与分析

测量、归因与分析

从竞价回调到转化和商业报表，使用签名、幂等和固定口径保持数据可解释、可核对。

测量与归因

  • win、loss、展示和点击回调使用 HMAC 签名与明确有效期
  • 展示/点击支持重复抑制；共享状态故障不阻止合法测量事件发布
  • 服务端行为接口支持转化、购买、下载、视频完成和命名自定义行为
  • 广告主事件 ID 幂等，同一投放链路按最近点击优先、浏览其次归因
  • 行为数据是分析事实，不会反向修改 CPM 账务或预算预留

报表与实验

  • 广告主、流量方和平台运营人员按登录账户查看各自范围
  • 展示、点击、CTR、行为、CVR、花费、收入、成本、毛利、ROI 与 ROAS
  • 统一 UTC、USD、数据来源、公式、刷新时间和部分数据说明
  • 确定性分组、追加式曝光与幂等结果支持受控对照实验
  • 实验只提供观察和分析，不自动修改竞价、预算或投放规则
数据口径：报表明确区分无数据、部分数据与零值；账务以已接受的展示事实为准，裸 win/loss 仅用于分析。
隐私与访问控制

隐私、身份与渲染安全

把隐私判定放在匹配与外部披露之前，并把账户权限、审计和素材执行限制在明确边界内。

隐私与数据治理

  • 识别适用的 GDPR/TCF v2.3、US Privacy、GPP、COPPA、GPC、DNT/LMT 信号
  • 缺失、拒绝、冲突或暂不支持的信号采用上下文投放；COPPA 使用受限模式
  • 所有模式移除精确坐标；上下文模式同时移除可识别用户和详细设备数据
  • 频控和测量标识使用分域 HMAC 假名，审计与外部请求分别清理
  • 日志、上传人群、行为和实验事实均有配置化保留与删除流程

账户与内容安全

  • 可选数据库会话、TOTP 双重验证、一次性恢复代码和会话撤销
  • 按角色、动作、账户和资源授权，敏感操作要求近期再次验证
  • 安全事件采用固定字段与不可变审计，敏感凭据不进入审计正文
  • 公共与工作台页面使用上下文转义，素材审核仅显示转义后的源内容
  • 可执行素材只在广告交付沙箱内加载，不作为管理页面的可信 HTML
启用边界：隐私最小化与渲染安全属于基础边界；强化会话、双重验证和细粒度权限由部署方完成密钥、邮件、迁移和权限验收后启用。
流量质量

流量质量与风险控制

采用可解释、可灰度、可复核的规则流程降低异常流量和错误结算风险，不以不透明模型自动定性。

信号与规则

  • 重放、事件顺序异常、来源/App 不一致和标识格式异常
  • 异常速率、异常 CTR、自动化证据和合作方策略信号
  • 规则版本依次经过草稿、观察、灰度、启用或停用
  • 支持观察、标记、限速、拒绝和隔离等分级动作
  • 证据缺失或不完整时自动降低处置强度，基础设施故障不作为异常流量证据

复核与账务边界

  • 广告主、流量方和合作方只能查看获授权的案件与受控证据
  • 案件历史、人工复核、申诉、独立处理和规则回滚均可审计
  • 无效流量只生成排除、暂缓或冲正建议，账务变更仍需单独审批
  • 内部事件与合作方标识使用 HMAC 摘要，证据和聚合记录有保留期限
  • 投放节点读取有界不可变快照；快照过期后不以旧规则继续阻断流量
启用边界：流量质量模块默认关闭，需完成权限、规则、证据来源、观察期、误判率、申诉和回滚验收后分阶段启用。
账务与结算

账务、结算与托管支付

统一广告主计费、流量方收益和外部需求方成本口径，并把账单、审批、付款状态和异常核对保留为可审计记录。

账务与人工结算

  • usd-cpm-impression-v2 统一以 USD CPM 记录竞价并按 CPM/1000 结算展示
  • 分别记录广告主费用、流量方收益及外部需求方 charge/pay/margin
  • 按日、周或月生成不可变来源快照和稳定 CSV 导出
  • 调整、确认、结算和更正使用追加记录，不静默修改原始投放事实
  • 创建、复核和结算由不同操作人员完成，并保留外部凭证引用

可选托管付款与收款

  • 广告主可通过 Stripe Checkout 托管页面完成资金支付
  • 流量方可通过 Stripe Connect Express 完成收款账户资料提交
  • 平台只保存不透明的服务商对象标识，不接收或存储完整卡号、银行账号和身份材料
  • 签名回调、幂等提交和绑定冻结防止重复入账或错误更换收款目标
  • 手续费、退款、争议、转账冲正和打款失败进入独立对账异常流程
启用边界：人工账单是持续有效的财务依据和故障后备。托管支付默认关闭，测试或正式模式均需另行完成法务、财务、税务、风控、隐私和客服审批。
管理接口与运维

开放 API 与生产运行

把外部管理接口、流量准入、缓存发布、运行指标和恢复流程作为同一套可版本化的平台工程能力。

广告主管理 API

  • 独立版本化的 /api/v1，以 OpenAPI 3.1 描述公开契约
  • 管理广告主资料、广告活动、广告组、素材、定向、发布操作和投放报表
  • 一次显示的服务凭证绑定单一广告主、固定权限、有效期、轮换和撤销
  • 写入使用 Idempotency-Key，修改使用 ETag，缓存生效通过操作状态确认
  • Redis 分别限制凭证和广告主配额，跨账户访问在资源边界拒绝

流量与可用性工程

  • 按合作方控制 QPS、并发、正文、解压大小和请求时限
  • 受保护指标覆盖拒绝原因、延迟、依赖、缓存新鲜度、队列和回调

使用说明与常见问题

页面显示“已保存”，为什么投放或广告位行为还没有变化？

运行请求读取缓存而不是直接查询数据库。请先确认对象状态正确，再联系运营方检查缓存是否已经刷新到运行节点。

广告主已经有广告素材，为什么仍然没有竞价？

依次检查账户与上层对象状态、投放时间、预算、素材尺寸、USD 竞价底价、供应侧流量范围和人群定向。只启用广告素材不足以绕过上层规则。

流量方请求返回 200，但广告内容为空，是否表示故障？

不一定。合法请求在没有合适广告时也会返回 200，空字符串或未填充对象属于正常 no-fill，客户端应隐藏或回收对应容器。

报表为什么不是即时更新？

展示、点击和账务数据由日志聚合与定时任务生成，因此会有处理延迟。上线验收时请同时记录测试时间、账户、活动或广告位信息。
